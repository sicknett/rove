# Audit 2026-11-25 — watch history, Continue Watching, tracking, title page, library

Code-read audit. Each line: where, what the user sees, the fix. Paths are under `ui/src/`.
Real data note: the owner's history is keyed by TMDB-style ids (`tmdb:693:3:15`, `metaId: "tmdb:693"`).

## High
- [fixed] T1 `state/history.ts:230-237` (`applyRemote`) — sync deletes a resume point that is newer locally than on the tracker: the Continue Watching card for what was just watched disappears after start and returns later, stale. Fix: when local is newer keep it and queue a `resume` op.
- [fixed] T2 `tracking/idmap.ts:51,61-65` — failed id lookups are cached forever (`null`), so titles stay `tmdb:`-keyed and the PublicMetaDB adapter silently skips them (`tracking/adapters/pmdb.ts:128,145,156`). Fix: do not persist negatives (or short TTL); a failed lookup is "unknown"; surface skipped ops as a sync problem.
- [partly: every history read and write in the title page, card menus, cards, Continue Watching, the library screens and the launch (so Hero Play too) goes through the title's history id, and `tmdb:` entries move to the IMDb id on load, after each pull and whenever a mapping is learned. Left: `screens/home/Hero.tsx` still reads `library[meta.id]` for its watchlist button (it should use `useInWatchlist` from `library/watchlist.ts`)] T3 `screens/title/Title.tsx:34-43,136,140,244,270`, `player/launch.ts:40-45` — no canonical title id: opening a show from a `tt…` card while history is `tmdb:…` shows no ticks, no progress and "Play S1 E1". Hero Play (`screens/home/Hero.tsx`) and card menus (`media/actions.tsx:32,39-40`) write under the raw card id. Fix: one canonical id (IMDb when known) at every read and write, and migrate existing keys on load.
- [partly: one card per title under canonical ids; `cards`, `library`, `dismissed` and the Continue Watching and History grouping are keyed by a title key that carries the type for `tmdb:` ids. Left: the watch key of a `tmdb:` movie and of a series-level mark with no season/episode can still be the same string (`watchKey` is shared with the player and was not changed)] T4 `library/continue.ts:64-69,92-101`, `screens/library.tsx:124-128,245-248`, `state/history.ts:70-74` — the same show under both id forms gives duplicate cards; `cards`/`library`/`dismissed` keyed by metaId without type (TMDB movie 693 and TV 693 collide). Fix: canonical ids; include type for `tmdb:` ids.
- [fixed] T5 `addons/client.ts:118-131`, `data/hooks.ts:140-156`, `player/launch.ts:20-28,121-128` — `tmdb:` entries only work if the addons accept `tmdb:`: otherwise no art, no "next episode", "No metadata addon knows this show", or the source picker opens with no addon. Fix: fall back to the IMDb id through the id map for metadata and streams; play the card's own season/episode when the meta lacks it.
- [fixed] T6 `state/history.ts:142-149`, `player/runtime.ts:81-93` — past 90 % "watched" is rewritten and re-pushed every 5 s until the video ends (duplicate plays on Trakt). Fix: return early when already watched this session.
- [fixed: `leaveVideo()` in `player/session.ts`, called on episode and source change, on leaving the player and on the window closing] T7 `player/runtime.ts:109-115`, `player/session.ts:176-187`, `App.tsx:78` — the last position is never pushed when the app closes or the episode changes. (Same as P8/P22.)
- [fixed] T8 `tracking/sync.ts:54-65`, `state/history.ts:230-241` — connecting a different tracker or account wipes previously synced history (`synced: true` is not tied to an account). Fix: clear `synced` flags on connect/disconnect.
- [fixed] T9 `tracking/pmdb.ts:164-171,184-190`, `tracking/adapters/pmdb.ts:54-64`, `simkl.ts:135`, `mdblist.ts:78` — one bad or partial pull deletes local history (non-JSON body parses as empty; failed playback fetch caught as `[]`). Fix: throw on parse or partial failure; skip the deletion step unless the pull is complete.
- [fixed] T10 `tracking/sync.ts:94`, `state/history.ts:252-256` — outbox changes are lost if the app closes mid-push (`takeOutbox()` empties it first). Fix: remove an op only after it is sent.
- [fixed] T11 `addons/client.ts:122-130`, `data/hooks.ts:26-32,141-147` — a transient metadata failure is cached as "no such title" for hours. Fix: throw when every candidate errored; null only for a real "not found".

## Medium
- [fixed] T12 `library/watchlist.ts:16-21`, `tracking/sync.ts:127-136` — watchlist sync is one-way and unqueued (offline adds lost, failed removes come back, tracker-side removals never arrive). Fix: outbox + reconcile against a last-synced snapshot.
- [fixed] T13 `screens/title/Title.tsx:378`, `meta/tmdbSources.ts:16`, `tracking/sync.ts:130-134` — watchlist duplicates and ghosts across id forms. Fix: canonical ids.
- [open: not verified against Simkl's API, so the call is unchanged. Removals now go through the outbox, which sends this same request] T14 `tracking/adapters/simkl.ts:223-226` — Simkl "remove from watchlist" calls `/sync/history/remove`; may delete history. Verify against Simkl's API before relying on it.
- [fixed] T15 `screens/title/Title.tsx:196-202,260-262,294-297` — bulk marks re-mark already-watched episodes (dates overwritten, extra tracker plays). Fix: skip keys already watched.
- [fixed] T16 `screens/title/Title.tsx:244,260` — "Mark season watched" never flips for a season still airing. Fix: compute over aired episodes.
- [partly: the next episode in order is offered while the latest mark is known to be a repeat (`plays` on the mark: counted locally, taken from Trakt's play counts and from trackers that list each play, or because a mark shows up with a date well after the one known here). Left: a rewatch started on another device, on a tracker that keeps one date per episode and no count, is only seen once this device has known both the old date and the new one] T17 `library/continue.ts:55`, `player/launch.ts:50-55` — rewatching a finished show never offers the next episode. Fix: when the latest watch is newer than the following episodes' marks, offer the next in order.
- [fixed] T18 `screens/home/Home.tsx` (ContinueRow), `media/cards.tsx:33-36,60` — poster-style Continue Watching cards open the title page instead of playing, lack Remove/Mark watched, subtitle cut to 9 characters. Fix: pass `continueKey`, season, episode; click plays; real subtitle prop.
- [fixed] T19 `tracking/sync.ts:138-176`, `App.tsx:102-120` — profile switch during a running sync writes one profile's data into another. Fix: capture the profile id at start and bail if it changed; reset module state on load.
- [partly: the exact local position is kept when the tracker gives back the same share (within 1 %) or the capped one. The 79 % cap itself stays until it is checked against each API whether a pause past 80 % counts as watched] T20 `tracking/adapters/trakt.ts:191`, `simkl.ts:190`, `mdblist.ts:109`, `state/history.ts:236` — Trakt/Simkl/MDBList echo back a degraded resume point (79 % clamp; exact local position overwritten by percent × nominal runtime). Fix: no clamp; keep local position when the remote percentage matches within ~1 %.
- [fixed] T21 `screens/library.tsx:260-262,275,324`, `screens/title/Title.tsx:273,325` — episode dates one day early west of UTC and a bogus time in Calendar. Fix: treat date-only / midnight-UTC values as local calendar dates.
- [fixed] T22 `library/continue.ts:66,107` — entries with no timestamp are permanently hidden from Continue Watching (`dismissed ?? 0 >= 0`). Fix: compare only when a dismissal exists.
- [fixed] T23 `screens/library.tsx:131-132`, `data/hooks.ts:189` — History tab shows blank "?" posters past the first 60 titles.
- [fixed] T24 `data/hooks.ts:134-148`, `screens/library.tsx:96` — Library → Continue Watching fires up to 200 series-meta requests at once. Fix: cap concurrency; derive "next" only for recently watched shows.
- [fixed] T25 `tracking/sync.ts:107-176` — sync engine gaps: a permanently failing op blocks every pull; rejected/skip ops dropped silently; "Sync now" during a push pulls nothing. Fix: per-op attempt limit, pull even when the push failed, a "run again" flag.
