# Audit 2026-11-25 — player

Code-read audit of `ui/src/player/*`, `ui/src/sources/select.ts`, the bridge and `shell/src`.
Each line: where, what the user sees, the fix. Paths are under `ui/src/` unless they start with `shell/`.
Status is filled in as items are fixed.

## High
- [fixed] P1 `player/session.ts:270` — every Play waits for the slowest stream addon (up to ~90 s on "Finding the best source…"): the "first addon answered" branch is ANDed with `answered === total`. Fix: decide once the first addon has answered and a short cap timer has run; use `sources.pickerTimeoutSec` (never read today) as the cap.
- [fixed] P2 `player/session.ts:181`, `player/runtime.ts:194` — a dead link is remembered as working at `loadfile` and reused for hours. Fix: remember the link on the first `playback-restart`; keep an explicit `session.reused` flag; `forgetLink` on any load error.
- [fixed] P3 `player/runtime.ts:189-201` — endless "That link has expired. Finding a fresh source…" loop when a title has exactly one source. Fix: use the `reused` flag and allow one recovery per video.
- [fixed] P4 `player/store.ts:127`, `player/session.ts:310,326`, `player/Player.tsx:617` — position lost after a failed or slow source switch (mpv reports `time-pos` null → 0). Fix: keep `lastGoodPosition` per session (updated only while not loading and duration > 0) and use it for `currentPosition()`, Retry and recovery.
- [fixed] P5 `shell/src/main.rs` (`keep-open=yes`), `player/Player.tsx:466,480`, `player/store.ts:134` — end of file is never handled: a film ends frozen and paused, Up Next countdown freezes if the video ends first, "Skip Credits" on a movie jumps to a frozen end. Fix: react to `eof-reached` becoming true (next episode, or leave the player for a film/last episode); do not gate the countdown on pause when at end.
- [fixed] P6 `player/Player.tsx:453-457` — Up Next card never retracts after seeking back; countdown keeps running. Fix: when `timePos < at - 5` return the card to hidden and reset the countdown.
- [fixed] P8 `player/Player.tsx:119-126,144-145`, `player/runtime.ts:109-116`, `player/session.ts:176` — episodes stay "in progress" when advancing before 90 % (long credits, auto skip-credits, Next); and the "leaving this video" save is a no-op because `startStream` zeroes `duration` first. Fix: `playNext` marks watched when past the credits marker or lead time; capture position and duration before patching state.
- [fixed] P9 `player/SourcesSheet.tsx:18-27,55,89` — "No sources found" when sources exist: resolution/addon filter persists across titles while its chips are hidden. Fix: reset filters when the target video changes; fall back to "all" when the value is absent.
- [fixed] P10 `player/Player.tsx:158-159,653-663` — keyboard shortcuts die after touching the volume slider (focus stays on the range input). Fix: exempt `type=range` from the bail-out or blur on pointer-up.

- [fixed] P14 `player/store.ts:134`, `player/session.ts:323-328` — a link that dies mid-playback looks like a frozen pause. Fix: treat end-of-file well before the duration as a failure with Retry / fresh sources; refetch in the switcher when the list is old.

- [fixed] P16 `player/session.ts:224`, `servers/index.ts:105-109`, `player/runtime.ts:149-152` — reused links lose stream metadata (no server progress reports on resume; worse subtitle matching). Fix: store the whole stream in the remembered link.

- [fixed] P19 `player/Player.tsx:144-145,122` — "Are you still watching?" never appears with auto skip-credits. Fix: pass `auto = true`.

- [fixed: page side in `Player.tsx`; in `shell/src/main.rs` full screen is ignored during picture in picture and leaving it restores the windowed size, maximized and full-screen state] P21 `player/Player.tsx:273,191,250,372`, `styles.css:767-775`, `shell/src/main.rs:750-806` — picture in picture: mini window cannot be moved; F/double-click put PiP into full screen; leaving PiP from full screen restores wrongly. - [partly: last position saved and queued for the tracker, stop report sent, then the documents are written; the tracker itself only receives it on the next start, since a push cut off by the exit would lose outbox entries] P22 `App.tsx:78` — closing the window mid-play does not sync the final position or report stop to a media server. - [fixed] P23 `player/session.ts:165,273,327` — source switcher shows a partial list after a quick start. Fix: do not abort remaining fetches on start.
- [fixed: `Player.tsx` plus the guarded, caught launches in `player/launch.ts`] P24 `player/launch.ts:116-118`, `player/Player.tsx:119-126,468-471` — next-episode failures are silent ("Next episode in 0" forever); Back during the await still starts the next episode. Fix: try/catch with a toast; ignore the result if the session changed.
